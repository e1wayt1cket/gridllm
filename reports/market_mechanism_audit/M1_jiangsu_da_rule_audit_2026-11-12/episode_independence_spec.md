# Episode 独立性规格（M1）

- 状态：**方案，不含实现**。
- 依据：`10_DECISION_LOG.md` D-003、`00_PROJECT_CHARTER.md` §4。

---

## 1. 定义

**一个交易日 = 一个 episode。**

- 时段数 96，每段 15 分钟（R-05，第七十条）。
- episode 的边界是 **D-1 10:30 申报截止** 到 **D 日 24:00 结算完成**。
- episode 之间 **完全独立**：不共享 SOC、不共享计划、不共享结算、不共享履约义务。

---

## 2. 重置清单

每个 episode 开始时重置：

| 状态 | 初值 | 依据 |
| --- | --- | --- |
| 各储能 SOC $e_{k,1}$ | 0.50 | D-004、宪章 §6 |
| 计划量 | 无 | — |
| 结算累计 | 0 | — |
| 履约/考核状态 | 无 | — |
| 上日价格、上日中标 | **不作为状态** | 只能作为可公开的历史统计进入观测 |

每个 episode 结束时：

- 日终 SOC $e_{k,97}$ **自由**，不调整，不补偿，不回写（D-004）。
- 日终不产生任何"必须等于 0.5"的约束，也不产生反向的强行放电/充电。

---

## 3. 可以跨 episode 延续的东西

只有"学习"本身：

| 对象 | 是否跨日 | 约束 |
| --- | --- | --- |
| Actor / Critic 网络参数 | 是 | — |
| 优化器状态、目标网络 | 是 | — |
| Replay buffer | 是，可含多日 | **必须保留 episode 边界**（§4） |
| 归一化统计 | 是 | 只能来自训练集 |
| 评估结果 | 是 | 只作记录，不反馈进训练 |

**不得** 跨日延续：SOC、库存估值的历史值、上日申报、上日结算现金、任何"欠账"。

---

## 4. Replay 与自举的边界

多日 replay 是允许的，但有三条硬约束：

1. **每条 transition 带 `episode_id`**，采样时按 episode 组织，不能把 A 日最后一帧与 B 日第一帧拼成一条序列。
2. **n-step 回报与 GAE 不得跨越 episode 边界**；边界处自举值取 0（终止）而不是下一日的首状态。
3. **验证集的日子永不写入 replay**（`.claude/rules/data_governance.md` "Leakage"）。

---

## 5. **本规格最重要的后果：episode 只有一个决策**

在忠实的日前市场下（D-1 一次申报、D 日不再修改），一个 episode 里 agent **只做一次决策**：

```
D-1 10:30 之前：观测 s（D-1 及以前的信息）→ 动作 a（96 时段申报）→ 提交
D-1 17:30    ：出清结果（外部给定，不可干预）
D 日          ：按中标执行，按节点价格结算
               → 奖励 r（当日 payoff）
```

于是：

| 问题 | 现状 | 忠实日前 |
| --- | --- | --- |
| episode 步数 | 24 块 × 4 段 = 96 步 | **1 步** |
| 动作时间粒度 | 每块 | 全天一次 |
| 状态转移 | 由策略动作驱动 | **无内部转移**：环境在同一 episode 内不再产生新状态 |
| MDP 性质 | 序贯 | **一次性决策 / 上下文赌博机** |

**这必须写进报告，不能含混过去。**

后果：

- 现有 24 块滚动设计（`rl_b3_env` 的块循环）在忠实日前下 **没有对应物**。它的"日内 LMP 反馈"是实时市场信息，不属于日前。
- "MATD3 能做多步信用分配" 这一优势在单步情形下用不上；算法仍可运行（一步 MDP 是 MDP 的退化情形），
  但研究结论必须表述为"多智能体单步博弈中的策略学习"，不能表述为"多步协作学习"。
- 若坚持要保留序贯结构，唯一合法的做法是 **把 D 日的实际执行作为环境内部过程、不给 agent 新的决策权**
  （即 agent 的动作在 96 个时段上被"逐步执行"，但**不产生新的观测-动作对**）。

**这一条列入裁决项 Q-E1（见 `M1_decision_report.md`）。**

## 6. 日采样

| 项 | 规格 |
| --- | --- |
| 训练日集合 | 53 天（`data_manifest.counts.train`） |
| 每轮最少覆盖 | 全部训练日各 1 次（`minimum_rounds`） |
| 日顺序 | 随机打乱，但按轮统计覆盖 |
| 验证日 | 11 天，只用前向，不写 replay |
| 测试/节假日 | **不参与任何训练或选择**（`.claude/rules/data_governance.md`） |

现状的 `exposures_per_day_min/max` 与 `episodes_per_seed` 口径建立在这个日集合上；
`src/training_contract.py` 的不变式 **不变**，但若 episode 步数从 96 变为 1，
`block_steps_per_seed` 的含义需重新定义——**这是 M2 的范围，本阶段只标记。**

## 7. 与现状的逐项对照

| 项 | 现状（v4 协议） | 本规格 | 差异性质 |
| --- | --- | --- | --- |
| 每 episode 决策次数 | 24 | 1 | **结构** |
| SOC 初值 | 0.5 | 0.5 | 一致 |
| 日终 SOC | 钉 0.5（`terminal_soc.final = 0.5`） | **自由** | **结构**（D-004） |
| 跨日状态 | 无 | 无 | 一致 |
| Replay 跨日 | 支持 | 支持，需 `episode_id` | 小改 |
| 观测中的日内价格 | 有 | **无** | **结构**（泄漏，见 `data_information_timing_spec.md`） |
