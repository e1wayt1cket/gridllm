「报价是否影响出清」「市场力是否存在」之类问题的正确提法。

## 1. 当前出清数学模型是什么

完整推导、变量界、约束登记见 `clearing_model_current.md`（变量表、目标 O1–O9、
约束 C01–C26）、`objective_terms.csv`、`constraint_register.csv`。此处只复述骨架。

**模型**：33 节点辐射网（IEEE33，`line_impedance_scale 0.5`，`reactive_fraction_of_load_q 2.0`），
24 个结算块，每块一次 16 时段滚动 SOCP（`socp`，Gurobi，`Method=2`，
`QCPDual=1`，`BarHomogeneous=1`），只执行前 4 段。

**单窗目标**（最大化，`dt = 0.25 h`，`γ = 0.997`，`c = 100 CNY/MWh`，`π^u = 2500 CNY/MWh`）：

```
max  Σ_t dt·[ Σ_a b·served − Σ_{a∈N_a} γ^t(b·ch + o·dis) − Σ c·(ch+dis)
             − Σ_{a∉N_a} o·(pv+wind+dis) − Σ π^u·unserved − w_t·p_grid_t ]
     + γ^T·TV·Σ e_a·soc_{a,T}
     + Σ_su[ −dt·Σ_t(b·ch + o·dis + c·(ch+dis)) + γ^T·TV·e·soc_T ]
```

九项里真正有经济含义的是四类：**用能价值 O1**、**购电成本 O7**、
**储能双向报价 O2/O3**、**周期成本 O4**。其余（碳、绿电、弃电、slack 惩罚）
在 live 配置下 `enable_multi_objective: false`，代码存在但不进目标
（PASS，`src/dispatch_socp.py:596-613`）。

**结构判定**（PASS，逐条有代码位置）：

1. **没有 bid/ask 撮合**。每个主体只在供给侧（`dis`、`pv`、`wind`）或需求侧（`served`）出现一次，
   两侧不交叉。所谓「报价」是同一个人在目标函数里给自己写的系数。
2. **没有容量市场、没有辅助服务、没有跨主体约束**。所有跨主体耦合都走物理潮流（C02、C03、C12）。
3. **储能是「可两向消费/生产的节点设备」**，不是市场主体。它的 `charge_price` 只出现在 O2 里
   作为充电的边际成本，`discharge_price` 只出现在 O3 里作为放电的边际成本。
4. **外部电网是最后一个买方/卖方**，见 §2。
5. **互斥二进制不启用**（`exclusive_mode: off`），充放电互斥靠净功率变量 `net` 的重构实现
   （`src/dispatch_core.py:63-101`），因此同时充放**不可表示**——这是 PASS 的代码事实，
   与旧记忆里「同时充放」的问题已经不是一个机制。

## 2. 外部电价与内部 LMP 是什么关系

### 2.1 外部电网的角色（PASS，代码事实）

`add_grid_exchange`（`src/dispatch_core.py:151-190`）：

- 唯一平衡节点 b=0 上注入 `p_grid`，进 C02 节点有功平衡；
- `p_grid ∈ [−2.5 MW, +∞)`：**进口无上限，出口被限在 2.5 MW**；
- O7 以 `w_t`（外生的 `jn2025` 日内价格曲线）计价。

含义：外部电网在当前模型里是**无限量、按已知价格供应的边际机组**，
同时是一个**受限的收购方**。它没有报价、没有爬坡、没有容量，只有一条价格。
它在数学上等价于「一个价格等于 `w_t` 的无限容量发电机 + 一个 2.5 MW 上限的出口负荷」。

### 2.2 节点 LMP 的形成（推导 PASS，数值 NOT_TESTED）

LMP = `−Pi[t,i] / dt_scale`（`src/dispatch_socp.py:717-718` → `src/money.py:34-46`），
`Pi` 是 C02 节点有功平衡的对偶。在 b=0 处，`p_grid` 是松弛变量，
故 `Pi[0,t] = −w_t·dt`，即 **`LMP[0,t] = w_t`**（INFERRED，解析推导，
须由有限差分确认，而有限差分属于独立后续任务，本阶段 NOT_TESTED）。

内部节点的 LMP 与 `w_t` 的差来自三处：网损的影子价、线路容量的对偶（拥堵租金）、
以及储能报价与周期成本进入的边际成本。前两项在代码里存在，**幅度未测**
（NOT_TESTED：需要重算一天）。

另有一个**必须记住的口径**：`price_formation_audit.csv` P02 记录的「每格回退到 `wholesale[t]`」
（`_extract_lmp` 的对偶缺失保护）意味着——只要某格对偶取不到，该格 LMP 直接等于外部价，
空间差异被抹平。**该保护是否触发过，本阶段 NOT_TESTED**（需读运行产物）。

### 2.3 五种「电价」不可混用

报价（`charge_price` / `discharge_price`）、出清价格（`price`，跨节点均值）、
节点 LMP、ESS 实际结算价格（其所在节点 LMP）、ESS 收益（`participant_payoff`）
是五个不同对象，逐项对照见 `price_formation_audit.csv` P01–P13 与
`settlement_reconciliation.md` §4。混用其中任意两个都会得出矛盾结论。

## 3. ESS 报价是否真的影响出清

分成两层，答案不同。

### 3.1 机制层：PASS

- 报价确实进目标：`src/dispatch_socp.py:584-586`（自持 prosumer 分支，带 `γ^t`）
  与 `:92-95`（独立储能分支，**不带** `γ^t`）。
- 报价确实改变边际条件：`charge_price` 抬高 → 充电边际成本抬高 → 少充；
  `discharge_price` 抬高 → 放电边际成本抬高 → 少放。
- 报价的单位是 CNY/MWh，与 `w_t`、`cycle_cost` 同量纲，可以直接比较。
  因此「报价 = 0 时储能只被 `cycle_cost` 与 LMP 差驱动」是成立的。

### 3.2 幅度层：NOT_TESTED

本阶段没有重算，所以**没有任何证据表明报价变动会显著改变充放电量或 LMP**。
凡是「储能已经行使市场力 / 报价无效 / 报价影响很小」一类判断，本审计都不支持。

### 3.3 三个必须先解决的结构事实

**F1. 报价只能单向偏离真值（PASS，代码事实）。**
`ACTION_STORAGE_QUOTE_V4` 的界是 charge `(0, 150)`、discharge `(0, 300)`，
真值点在 **(0, 0)**——即**下边界**（`src/rl_spec.py:372-379`）。
于是策略**只能加价，不能减价**：不可能报出低于 0 的充电价（即不可能贴补充电），
也不可能报出低于 0 的放电价（即不可能免费放电）。
经济上这意味着**策略的表达能力被限制在「我要更多补偿」这一半空间**。
是否应当允许负价，属于设计裁决，不在本阶段。

**F2. 报价只覆盖 4 段，其余 12 段是真申报占位价（PASS，代码事实）。**
`reset` 把 96 段填满真申报点（`src/rl_env.py:837`），每块只覆盖 4 段（`:889-918`），
窗口 `[4k, 4k+16)` 的后 12 段用的是**真申报 (0,0)**，不是策略未来会报的价
（`information_timing_audit.md` §4）。
所以前瞻项优化的是「接下来 12 段我会诚实申报」条件下的最优，
而非「接下来 12 段我会最优报价」条件下的最优。这会影响当前 4 段的 SOC 路径
与边际条件，**方向与幅度 NOT_TESTED**。

**F3. 出清器对窗口内 16 段外部价完全已知，策略对价格曲线完全不知（PASS）。**
外部价整段切片进 O7（`src/rl_env.py:953`），策略只见到历史 LMP 与自身 EMA
（`:532-647`）。这是「市场完美预见、参与者没有」的信息不对称。
术语上把它叫「日前」或「日内」都会误导：它是**价格已知、负荷已知、
逐小时重开的确定性滚动市场**（`information_timing_audit.md` §5）。

## 4. 周期成本是否合理

四问四答，完整数据流见 `cycle_cost_dataflow.md`。

| 问题 | 回答 | 等级 |
| --- | --- | --- |
| 出清目标里收不收？ | 收，`c·(ch+dis)`，`c = 100`，**按总吞吐量**计，不对 `ch`、`dis` 分别打折 | PASS |
| 结算里收不收？ | 收一次，`participant_payoff._ledger` 的 `degradation` 项，同一口径 | PASS |
| 是否重复计费？ | **否**。目标里的 `c` 决定出清结果（数量），账本里的 `c` 决定现金流（金额），是同一个参数在两处各用一次，不是同一笔钱收两次 | PASS（`cycle_cost_dataflow.md` §5） |
| 奖励里收不收？ | 通过账本进 B 奖励；**不进** C2 势函数；**不进** 已废弃的 `two_settlement` | PASS |

需要人工注意的三处不对称，都属于设计裁决而非缺陷：

1. **prosumer 分支的报价带 `γ^t`，独立储能分支不带**（`:584-586` vs `:92-95`），
   而周期成本两边都不带。同一个参数在两套分支里的时间折扣处理不一致。
2. **周期成本对变量计价，不对能量计价**：`ch` 与 `dis` 各乘一次，充放一个来回
   的总成本是一个单程的 2 倍，等价于 `100/0.8464 + 100 ≈ 218.1 CNY/MWh` **交付电量**，
   或 **295.4 CNY / 满循环**。这个量级是否对应真实电芯折旧，不是本审计能判定的。
3. `two_settlement`（`src/market.py:21-51`）完全不含周期成本。它只被
   `src/run.py:221` 与 `src/ui/sim_page.py:700/1137` 调用，**不在正式路径上**，
   但 manifest 把这个名字写成了正式结算方式（见 F5）。

## 5. SOC / 终端值是否表达了真实的跨期价值

结论：**部分表达，且在真正需要它的地方恰好失效**。细节见 `soc_mpc_terminal_audit.md`。

- 期末估值 `+γ^T·TV·soc_T·e_max` 存在于每个窗口的目标里（`:614-618`，独立储能 `:98`），
  `TV = mean(wholesale)`（`:554-556`）。它是一个**规划影子价**。
- 在 `day_end`（第 24 块）与 `full_day`（结算）窗口里 `soc_T` 被硬等式钉住
  （`src/dispatch_core.py:31-57`），于是该项退化为**常数**，不改变 argmax。
- 因此：**日终没有期末价值，日内有；而在日内，这个价值是一个窗口均价的粗估**。
  这不是错误，是一个明确的建模选择，但它意味着「跨期套利能力」主要由
  `γ^t` 与 `TV` 决定，而不由任何真实的未来价格信息决定。
- 账本与奖励都没有期末项（`participant_payoff` 无 terminal 项，`c2_reward` 只有 SOC 势函数），
  所以**任何「库存价值」数字只能来自出清目标，不能来自账本**。

**F4（新增发现，结构性风险）**：末窗口的终端钉住是一个可能不可行的硬等式。
在 4 段窗口内从 `s0` 可达的末态是 `[s0 − 0.2717, s0 + 0.23]`，
命中 `0.5` 要求 `s0 ∈ [0.27, 0.7717]`；SOC 物理箱是 `[0.10, 0.90]`，
**没有任何约束阻止前 23 个窗口把 SOC 停在该区间之外**。
一旦发生：`dispatch_socp` 返回 `None` → `market.py:88` 打印回退 → 走逐时段引擎
（`market.py:116-138`）→ 第 23 块（**B 奖励唯一付费的块**）在另一套物理模型下定价。
代码层 PASS（路径可追），后果 INFERRED，**是否发生过 NOT_TESTED**。

## 9. M1 应考虑的机制（只列，不排序、不决策）

按「先量后改」的顺序列出，前四项都是**测量**而非改造：

1. **有限差分 LMP 验证**：扰动单点需求与单个报价，比对 `−Pi/dt` 与有限差分斜率，
   确认 §2.2 的解析推导。这是唯一能关闭 V10 / V11 / V12 的路径。
2. **报价–出清弹性测量**：固定同一天，单参数扫描 `charge_price` / `discharge_price`，
   记录充放电量与 LMP 变化，回答 H2 / H3。
3. **末窗口可行性普查**：不改代码，扫描既有 run 的 `train.log` / `episodes.csv`
   中的 `fell_back` 标记，回答 F4 是否发生过（H5）。这一项需要扩大授权到运行产物。
4. **空间价差普查**：读既有 run 的 `lmp` 数组，统计与 `wholesale` 的逐格差，
