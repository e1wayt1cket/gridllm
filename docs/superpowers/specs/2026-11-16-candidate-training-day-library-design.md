# 候选训练日负荷库设计（逐日选源，3.715 MW ±10%）

日期：2026-11-16。状态：设计已与用户确认方案，待审阅后进入实施计划。
本单元只产出负荷数据与验收证据，不修改出清器、训练协议或任何冻结文件。

## 意图

现有训练日负荷库（`reports/multi_user_load_2026-11-13/evidence/`）要求同一套 32 个真实表计在
每个训练日都数据齐全，结果只保留 2022-12-18/22/25 三天，全部在冬季。跨季节研究没有样本。

用户要求：以真实负荷数据为基础，选出足够多、跨季节、全网同时峰值在目标附近的训练日。
目标是 3.715 MW，容差 ±10%，即 `[3.3435, 4.0865] MW`。能凑多少算多少。

## 目标

1. 在冻结 split 的 53 个训练负荷日期（`data/processed/v2_cy_jn_2025/common_split.json`
   的 `near.train`）上，为每一天独立选出真实表计子集，使其全网同时峰值落在
   `[3.3435, 4.0865] MW`。
2. 每个入选日内部仍然完整真实：同日 96 点、不缩放、不拆分、不复制、不跨日拼接、
   不加合成背景、同一用户不重复计量。
3. 输出可复核、可重建的日库：逐日清单、逐日来源到母线映射、96×33 有功矩阵、
   输入输出哈希与独立复核结果。
4. 保持冻结证据不变：v1 三天及其出清结算产物一字节不动，新库使用新目录。

## 非目标

- 不验证出清、结算、定价或电压可行性。负荷在带内不等于市场可行。
- 不处理价格数据、不重做 split、不引入春季日期。
- 不修改 `src/da_market*.py`、`src/local_da_*.py`、`src/run_local_da.py`
  或任何把日库接入市场的代码。接入是后续独立单元。
- 不调整 IEEE33 网络参数、储能、新能源或无功能力。
- 不为凑数放宽本设计声明的任何规则（容差、每用户一表计、无缩放）。
- 不声称本库能解封 MATD3 训练：当前训练环境
  `data/processed/v2_cy_jn_2025/bus_loads_96x33.npz`（由 `src/v2_cy_jn_env.py` 读取）
  已覆盖全部 53 个训练负荷日、峰值 4.66–8.07 MW，本库与它不同源、不可直接替换。
  本库服务的是 `src/run_local_da.py` / `src/da_market_data.py` 那条 3.715 MW 真实负荷路径。

## 反目标

- 用缩放、复制、拆分或跨日拼接让某一天达标。
- 按出清结果、价格或收益反复调换来源或接线。
- 让未达标日期静默消失。所有 53 天都必须出现在清单里并写明原因。
- 覆盖或重写 v1 三天的证据。

## 方案比较

| 方案 | 做法 | 结论 |
| --- | --- | --- |
| A 逐日选源 | 每天独立选真实表计子集凑到 3.715 ±10%，逐日映射 | **采用**。唯一能横跨夏/秋/冬的方案 |
| B 分季固定集 | 每季一套固定来源 | 季内"全覆盖"要求让可用日更少，且是 4 个不同系统 |
| C 只放宽容差 | 沿用 v1 的 32 源固定集，容差改 ±10% | 只有 6 天，全是十二月，不解决跨季节 |

选 A 的理由：RL 的动作空间是四台储能的报价（`storage_quote_v3`，2 维/台），
负荷是外生数据而非参与主体，逐日更换负荷组成不改变参与者、动作空间或观察定义。
`2026-11-13-ieee33-load-mapping-proposal.md` 中"不同映射不能当同一系统"的顾虑针对的是
"负荷用户本身是参与者"的旧框架，在本训练设定下不适用。

## 选源规则（必须在运行前冻结）

对每个训练日 `d`：

1. **候选集**：来源池中该日合格的表计（`meter_sources.csv` 中出现的
   `(date, source_id)` 行，96 点完整、非负、通过既有质量筛选，且当日峰值 `> 0`——零峰值曲线
   不占负荷母线。每个表计属于唯一用户。当前来源池 4432 个表计日中无零峰值曲线，
   该条件为防御性规则。
2. **每用户至多一个表计**：同一用户在该日只能贡献一条曲线。
3. **填充**：对每个用户取其当日峰值最小的表计，按峰值升序排列（并列时按 `source_id`
   字典序）。依次尝试加入该表计，若加入后全网同时峰值仍 `<= 4.0865 MW` 则保留，
   否则跳过该用户。累加结果即该日的初始组合。
4. **抬升**：若初始组合的同时峰值 `< 3.3435 MW`，重复执行"单次上换"：
   在全部可行上换（换后同时峰值 `<= 4.0865 MW`）中取**换后峰值最大**的一个；
   若出现完全相同的峰值，取 `(旧 source_id, 新 source_id)` 字典序最小者。
   **一旦同时峰值 `>= 3.3435 MW` 立即停止**（不继续推向带宽上沿）；
   只有在没有任何可行上换时才提前结束。两种提前结束都原样记入 `reason`。
5. **判定**：最终峰值落在 `[3.3435, 4.0865]` 记为 `IN_BAND`，否则记为 `OUT_OF_BAND`
   并记录最终峰值与原因。两种情况都写进清单。
6. **确定性**：规则不含随机、时间或求解器容差依赖；同样输入两次运行必须产出相同字节。

**映射规则**：该日入选表计按匿名 `source_id` 字典序排列，依次分配到零基母线
`1..N`（`N` = 入选表计数，且等于有载母线数）。母线 `0`（Slack）不接负荷，
母线 `N+1..32` 需求为零。这是仿真接线，不声称真实地理分布。

**无功**：本库只输出有功，与 v1 一致（`reactive_power_generated: false`）。
无功口径由后续消费方声明，本库不生成。

## 验收标准

| 项 | 判定方式 |
| --- | --- |
| 53 天全部有结论 | `day_selection.csv` 行数 = 53，日期集合与 split 训练块逐一相等 |
| 入选日峰值在带内 | 每个 `IN_BAND` 的 `peak_mw ∈ [3.3435, 4.0865]` |
| 曲线真实且未被改动 | 每行映射的 `curve_sha256` 与来源池一致；矩阵逐点等于入选曲线之和，最大差 0 MW |
| 不重复计量 | 每日 `source_id` 唯一，`user_id` 唯一 |
| 节点覆盖与映射一致 | 有载母线数 = 入选表计数；母线 0 恒为零；`N+1..32` 恒为零 |
| 可重建 | 同一规则重跑，产物哈希一致 |
| 冻结证据未变 | `reports/multi_user_load_2026-11-13/` 与 `reports/load_selection_2026-11-13/` 哈希不变 |
| 规则错误会被拒绝 | 测试覆盖：超上界组合、重复用户、跨日拼接、缩放曲线、母线 0 接负荷 |

独立复核不得复用选源脚本的判定函数，须从来源池 `meter_curves_train.npz` 与
`meter_sources.csv` 重新构造每个入选日的 96×33 矩阵并逐点比对。

## 暂定可行性（侦察结果，不是验收结论）

用临时脚本按上述规则在冻结来源池上排过一遍，53/53 天可落入带内：
夏（07-23、08 共 13 天）、秋（10 月 11 天、11 月 13 天）、冬（12 月 16 天），
有载母线 28–32 个，峰值 3.348–4.085 MW，中位 3.925 MW。

这些数字来自一次性侦察脚本，不作为交付证据；正式结果以本设计的实现与复核为准。
`tmp/` 下的侦察脚本可删除。

侦察脚本与第 4 步规则的差别只在两点未声明的细节上，现已在上文钉死：
循环在峰值进入带宽时停止（若改成"无可行上换才停"，53 天会全部贴到 4.0856 MW 上限）；
并列取字典序最小。实现若偏离这两点，上面这组数字不再成立，属于实现错误。

## 风险与未覆盖

1. **峰值偏向带宽上沿**：39/53 天在中位 3.925 MW，高于锚点。"3.7 MW 左右"是带宽，
   不是常数；逐日峰值必须随清单一起报告，不得在报告里只写"约 3.7 MW"。
2. **同一天两个版本**：新库重新构造了 12-18/22/25 的负荷组成，与冻结 v1 不同。
   报告与产物必须写明版本；不得让同名日期在两版之间静默混用。
3. **物理未验**：有载母线 28–32 个、单点负荷比 v1 更重，而 12-25 已经贴死电压下界。
   夏天负荷很可能整片出清不了。`clearing_tested: false` 必须随库一起发布。
4. **价格仍是第一道门禁**：负荷日凑齐不等于训练解封；真实逐日价格曲线仍只有一条。
5. **春季不存在**：split 训练块不含春季，任何"四季"表述都是错的。
6. **本库不等于训练数据**：现行 MATD3 数据是另一套 53 天 4.66–8.07 MW 的
   `bus_loads_96x33.npz`；本库与它不同源。把本库接入训练是另一件事，
   需要单独立项，且会改变训练数据的尺度。
